This closes out the November 8 physical-feedback pass, not the earlier work documented in [development-performance-nov08.md](development-performance-nov08.md). The final closeout changed no production code; it reran the pending Data regression and audited the evidence. The dirty worktree and existing DEBUG scheme settings were preserved. No physical device, live OAuth, Web/backend change, deployment, commit, or push was used.

**Release of this pass for physical acceptance:** the WeiPo PBL fixture, the requested visual fixes, and the targeted Data retests passed in the simulator. The real WeiPo packet sequence that caused the reset, the physical Data rectangular flash and animation smoothness, and the actual Jiangmen page still need physical confirmation. Off-path 2x2 route solving was not implemented. The complete automated run had one failing Data test; passing targeted reruns do not turn it into a clean complete run.

## Root causes and implementation details

### WeiPo timing and Guidance

- The reproducible reset path is a classification problem: a native A3 can be authoritative for stickers even when preceding A5 events cannot certify the projected move history. The former generic continuity-break path treated that as invalid standalone timing, stopped the clock, and reset elapsed time. A malformed or ambiguous snapshot still cannot certify solved. A duplicate/backward modulo-256 A5 no longer moves the parser cursor.
- The native adapter preserves a uniquely renderable snapshot without promoting an uncertified move chain. The peripheral propagates a WeiPo-specific boundary through the routed canonical feed. Only a newer A3 with a same-counter accepted A5 carries the host turn receipt timestamp. During a standalone WeiPo solve, such a boundary keeps the timer alive, marks reconstruction incomplete, and may finish only on an authoritative rotation-equivalent solved state with a positive duration measured to that receipt. Save, penalty, and next-scramble machinery are reused. Existing GAN 3x3 and Timer-owned Combined timing were not redesigned. DEBUG events `weiPo.timing-snapshot` and `weiPo.timing-completed` distinguish snapshot trust, matched turn, solved status and save result.
- The previous 2x2 presentation only recognized target completion and hid live progress; the recovery solver entry remains 3x3-only. Checkpoints are indexed once for the scramble, including both intermediate quarter-turn states for each half-turn. The canonical key normalizes proper color frame/body pose using an ordered corner. The indexed state array starts at solved; the post-token prefix is at `index + 1`. This off-by-one was independently found by the first focused run and corrected. Where more than one prefix has the same logical state, the check is conservative except for the verified final target.
- Safe next design for full 2x2 recovery: establish a physically meaningful move frame (or an unambiguous instruction relative to the displayed pose), then use a dedicated corner-state solver and validate its moves against the current state and target under request revision/cancellation. Do not feed a native axis into the 3x3 solver or label unverified directions as physical turns.

### Data native transition and coordinate audit

- Kept the native Select/X button identity, native bottom accessory/selection controls, and existing transaction. The change in the root tab-minimization policy is the isolated application-side correction; the old physical recording does not separate its effect from the prior button identity change. No production sleeps, artificial offset adjustments, masks or animation replacements.
- Earlier 26.5 Dark frame sample: left x = 22.365, right max x = 384.365 in a 402 pt window; all three controls shifted by the same +2.365 pt, and all three still hit their UIButton. Absolute 20/382 asserts failed despite unchanged 362 pt span. Other failures in early runs sampled controls before they entered the viewport (e.g. y = 845, height = 44 in a viewport ending at 874); those are not dismissed as mere horizontal-origin differences.
- The final test waits until the leading UIButton is on-screen and actually hittable. Then it asserts every control is within the viewport, has at least 44 pt width/height, hits its own native UIButton, has the expected aggregate span and no overlaps, and checks red tint, wide/compact presentation, selected-count changes, and destructive confirmation without deleting the fixture data. It replaces an absolute frame assumption with the layout invariant; it does not declare an off-screen or obscured button acceptable. A persistent small translation of the *whole* bar can still pass those assertions. The two final Dark observations independently placed the left edge at 20.00 and 20.33 pt, with no persistent large translation seen. No production change was made to obtain those passes.
- In the completed iOS 27 A/B runs, 32 geometry samples per appearance: search enabled, viewport about 784–874 pt across the two appearances and bottom inset 0–139 pt; search disabled, viewport 874 pt and bottom inset 34–83 pt. Each run kept a constant offset within each tested list edge; bottom offsets differ across configurations because insets/content geometry differ. UIKit presentation-layer geometry varied in both configurations. Screenshots verify search is removed in the off branch and the tab bar/selection UI is retained. These samples distinguish layout participation from list-offset jumps, not painted pixels or frame cadence. No hypothesis about the actual rectangle's renderer is closed.

### Organizer and sharing

- The relevant Jiangmen surface is organizer HTML, not the structured competition model or a flattened attributed-text parser. The renderer now measures a margin-containing content root (larger of its rect and scroll height), suppresses identical measurements before the JS bridge, and removes the previous 30,000 pt clamp. It overrides author-imposed height/overflow only for common text elements and preserves wrapping, links, formatting, security policy and current-document nonce validation. Appearance and scaled text change the document content, not the WKWebView identity. The screenshot alone did not establish which of these conditions affected the live page.
- Report and Highlight share the existing badge artwork and output lifecycle. Report still encodes one PNG through bounded strips and rejects extreme limits explicitly instead of truncating. Highlight retains the approved editorial ordering, identity block and attempt visibility. The 4x rasterization is only for small Highlight badges; unrelated diagram/image exports keep the existing default scale.

## Risks and physical acceptance

- WeiPo: a final solved A3 with no correlated eligible A5 does not get an invented stop time. It can leave the timer running until further trustworthy evidence or user action. Check this and large counter jumps/reconnects on hardware; timestamp is a host receipt, not a newly verified device clock. Logical checkpoint equivalence can hide a physical-face distinction; it must not be used to invent recovery instructions.
- Data: a rapid change in native tab bar/accessory composition can still expose a transient region even if endpoint controls are correct. Very narrow layouts or extreme accessibility sizes may resort to icons. A narrow device/long translation and a four-digit count should be checked with VoiceOver and larger text.
- Battle: confirm status/home-indicator areas under real system chrome, small landscape and both X positions. No automated pixel-perfect concentricity tolerance or hardware touch/animation frame trace.
- Organizer: removing the artificial cap preserves long descriptions but malicious/extreme organizer documents can still incur WebKit layout cost. Complex author styles outside the supported text elements and dynamic remote image loads were not exhaustively covered.
- Sharing: the existing single-PNG format deliberately errors above its safety envelope; a huge export is not promised to succeed. Photos/share behavior for very long outputs remains a physical check.

1. WeiPo 2x2 standalone: use the affected PBL flow, first at normal speed and then rapidly. Check nonzero elapsed time, exactly one saved 2x2 result, next scramble, progress after a deviation and return, and reconnect/background restore. Spot-check GAN 3x3. If timing still fails, use DEBUG timing markers plus the relevant packet window, not unrelated captures.
2. Data on the affected iPhone: use the same Debug source and dataset. With `CUBEFLOW_DATA_DISABLE_SEARCH` unset, test one settled enter/exit and rapid reversals at both list edges, in Light and Dark. Repeat with only `CUBEFLOW_DATA_DISABLE_SEARCH=1` as a Run environment variable. Compare the rectangle and transition smoothness separately; remove the variable afterward. Report whether the rectangle persists in each branch, not just whether search disappeared.
3. Battle: open one, then both settings panels in both layouts. Inspect the safe areas, circular X, rotated title and event selection; verify the opponent can still stop and spot-check GAN timer and handicap.
4. Export a banner and no-banner Report and a minute-valued Highlight with a record. Check preview, Share and Photos. Open the actual Jiangmen organizer section at normal and enlarged text size; scroll through the last heading and verify the official link still opens.
