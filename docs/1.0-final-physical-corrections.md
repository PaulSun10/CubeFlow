## Shrink

The prior fitter already searched down toward zero; there was no remaining 45%
minimum to lower. It accepted an NSString/UIFont height estimate without checking
SwiftUI's actual intrinsic wrapped height, then clipped the viewport. An estimate
that underpredicts the real layout therefore has no corrective path.

Shrink now uses that estimate as its starting point, measures the rendered Text,
and decreases size again if its real height exceeds the existing safe region.
It resets on content, font or viewport changes, never adds scrolling, and keeps
an absolute 0.25pt floor only for pathological input. Content which fits stays at
its configured size. The Scroll mask/font/Timer gap were not changed.

Focused tests cover system and Avenir Next, 80/100/140/240/300-move text, two widths,
short text at unchanged 20pt, and real rendered feedback in a 220x60pt region with
an intentionally larger-than-estimated font. The original UIWindow/pixel Scroll
regression still passes. The feedback fixture initially observed a stale captured
size; observing size changes directly repaired the test, not the production fit.
Physical 6x6/7x7 reacceptance remains necessary.

Recognition identity is the ordered top/bottom pair of circular boundary rings.
A repeated sector ID is the interior of a two-sector corner. Only cyclic layer
alignment is quotiented out; neither reflection nor top/bottom sorting is allowed.
Counting still uses the precise aligned sector frame, not that recognition quotient.

Independent circular-tiling enumeration gives 29 participating layer geometries:
5 with two corners, 10 with three, 10 with four, 3 with five and 1 with six.

An independent legal-transition BFS reaches the same presentation set and 7,356

coverage. Normal CS has 169 non-cube-shape presentations. CSP also retains the
cube-shape context because even/odd parity still matters there.

Layer swapping is self-equivalent for 10 presentations. A rigid inversion swaps
AND reverses the layers, also fixing 10 presentations, but these are not the same
10 states: chiral pairs distinguish the two operations. Both quotients happen to
have 90 orbits. Equality of counts does not establish equality of semantics.

`square-one-presentation-audit.json`.

Its inverse/reference proofs were internally valid, but proved an inappropriate
user-visible identity model. Nested Normal/Inverted groups also changed setup pose
without changing the case's base diagram. The old 90/180/344 product conclusion
is withdrawn.

CSP now has 170 ordered visible presentation groups, each with Even/Odd children:
340 deterministic contexts, 339 reference formulas and one even cube-shape identity.
No nested Normal/Inverted choice remains. Inversion is a state transformation that
leads to its own presentation when geometrically distinct; symmetric recognition
states are not duplicated. Parity is relative to an explicit even reference and
counting alignment. It is exact piece-cycle state metadata, not a recognition
heuristic or a claim of equivalence to SpeedCubeDB's Cale color-count convention.

The 180 previous normal contexts are retained, including their opaque IDs, setups
and 179 formulas. The 164 separate nested inverted formula records are removed;
160 new standalone parity formulas fill the remaining ordered presentations.
Each new reference comes from a legal BFS path and is checked through actual
transitions. No blind cube-token/string inversion or curated algorithm collection
is used. These are mathematical references, not optimized speed algorithms.

The validator independently executes the already-bundled packed Square-1 model
for every setup. It also checks visible C/E label, ordered state ID, parity frame,
