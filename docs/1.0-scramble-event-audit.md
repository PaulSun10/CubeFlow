## FTO Workflow

`FTOScrambler` owns one cached JavaScriptCore VM on a private serial queue. The production Timer worker invokes it off-main. It samples a legal random state and solves/inverts through [Chen Shuang's pinned standalone MIT engine](https://gist.github.com/cs0x7f/1579492aa43c794d529057386c489702), rather than inventing a random-move fallback. Errors produce the existing unavailable result, not plausible-looking invalid notation. Tables are initialized once; device cold-start latency still needs measurement.

FTO now participates in regular event selection, refresh/prefetch, session/solve event storage, Data glyph/filter presentation, ordinary statistics, the algorithm data model and native/csTimer export. No competition-icon alignment, BLE behavior or special timing semantics were reimplemented.

The diagram adapter independently unfolds eight triangular faces with nine stickers each. Native face order is `U,F,BR,BL,D,B,R,L`; within a triangle, rows have 1/3/5 stickers. Corners occupy indices 0/4/8, edges 1/3/6, centers 2/5/7. Unique shared grid edges are stroked once after all fills. Face colors are independently configurable through the existing native puzzle palette editor. Old configurations missing the FTO field retain their prior custom palettes.

An external `cubing@0.63.8` puzzle-geometry/KPuzzle model was used only as an independent oracle, not as an implementation dependency or source of copied solver code. All 72 stickers agreed for **98 vectors**: single turns, a mixed sequence, all 16 new case setups and 64 deterministic mixed sequences. Eighteen independently computed full-state fixtures are bundled for deterministic native tests. The sticker correspondence is uniquely established on the calibration sequences; independent single-turn permutations constrain arbitrary compositions, not just color totals.

## Raster Root Cause

NxN formerly stroked each polygon on a canvas whose logical boundary nearly coincided with its path. Half of an outer stroke could lie outside the backing bitmap; adjacent fills could erase internal stroke halves. SwiftUI padding cannot repair a stroke clipped during rasterization.

The raster helper fits content inside an explicit device-pixel stroke margin, uses one backing-pixel grid phase/width and draws fills before a single grid path. NxN intrinsic dimensions/aspect ratios include that margin. FTO uses the same stroke-safe backing contract. WKWebView rasterizes at the final fitted size and DPR, so the final image is not merely an intrinsic-sized bitmap with thin lines downsampled by CSS.

The offline real-browser fixture checks NxN 2-7 and FTO at 52/160/320 point widths and DPR 1/2/3, plus all 16 FTO case images. It checks alpha bounds, outermost backing pixels, both light/dark final compositions, equal-area/nonoverlapping FTO triangles and resolvable outer/internal NxN stroke widths. This is browser raster evidence, not physical WKWebView/SwiftUI acceptance.

## Backup And Interchange

Native format version 2 gains optional `inputSourceRaw` and opaque `reconstructionData` fields. Unknown future source values survive; old backups decode without inventing provenance. On updating an existing solve, an absent legacy optional field does not wipe existing metadata. Solve event, time, penalty, timestamp and session ownership remain separate. There is no destructive model migration.

csTimer has one scramble type per exported session. Mixed-event CubeFlow sessions are now partitioned **in the export only** so FTO/OH/BLD are not relabelled as the majority event. Local solves are not moved. Current csTimer IDs are emitted; legacy CubeFlow aliases are accepted on import. A declared scramble type wins over misleading session-name heuristics.

csTimer cannot represent BLE reconstruction/timestamp provenance or every CubeFlow generator/activity variant. Use native backup for lossless CubeFlow metadata; do not claim a csTimer round-trip is lossless. Exporting a mixed session may import as several sessions, by design.
