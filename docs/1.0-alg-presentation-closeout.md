# Alg Presentation and Timer Closeout

## Scope and Boundaries

This pass preserves the existing dirty worktree and the accepted PB, Data,
canonical learned identity, FTO, BLE, Combined, Explore and competition behavior.
No algorithm collection, renderer implementation, or external image was imported.
No commit, push, deployment, or deployment-target increase was performed.

## Timer Rendering

The prior Scroll protection depended on a local viewport proposal and an
asynchronously published Timer frame. The scramble Text also retained its own
transition. Clipping that local proposal did not establish a compositor boundary
against the independently positioned Timer at the common ancestor. This is the
structural gap addressed here, not a claim that a simulator reproduced every
aspect of the reported physical 7x7 failure.

The touch Timer now publishes a bounds anchor before its `.position`, resolved in
the root overlay. Ordinary controls/scramble content is masked there at exactly
`actualTimerFrame.minY - 12`. A matching content shape prevents masked overflow
from extending its touch region into the Timer. The same resolved boundary feeds
the available-height calculation. The outer mask is independent of the child's
cached/animated height. Font size is unchanged in Scroll; no puzzle-specific
height, blanket padding or large reserved region is introduced.

Shrink uses the same available region, measures the configured UIFont's complete
wrapped text, and binary-searches down from the configured maximum until it fits.
It has no ScrollView and no fixed 45% floor. Rendering uses the measured UIFont;
custom-font Dynamic Type scales the maximum before fitting rather than scaling
the fitted result twice. Multi-blind's independent entry button
is retained. Smart Cube progress presentation/lifecycle is unchanged.

The regression fixture hosts a real SwiftUI ScrollView/Text in a UIWindow, uses a
real positioned Timer Text bounds anchor, deliberately supplies a stale 450pt
child proposal, and examines rendered pixels before and after scrolling. It
includes 6x6/7x7-sized fixtures and 5,000 synthetic move tokens. Shrink separately
renders long text at two constrained widths and checks complete text height.

Physical acceptance remains necessary: 6x6 and 7x7 Scroll and Shrink, both scroll
ends, Timer vertical offsets/fonts, portrait/landscape and accessibility sizes.

## Stroke Topology and Enlargement

NxN face perimeters are now closed paths with miter joins. Internal grid edges
are drawn after fills in the same stroke operation and meet the continuous
perimeter. The previous independent butt-ended perimeter segments left missing
corner quadrants. Pixel snapping, fitted bounds, palette and stroke multipliers
1 / 1.6 / 2.6 are unchanged.

The focused browser raster fixture covers 162 renders (2x2 through 7x7, three
widths, three backing scales, three stroke levels), 594 uniform edge-width checks,
and 2,592 closed-corner checks, including final light/dark composition boundaries.
It does not run or alter the frozen FTO solver/state fixtures.

Removed scramble-only enlargement: Timer eye entry, sheet state/presentation,
inline tap-to-open, private enlarged viewer, pinch container and viewer-only
overlays/actions. Inline diagrams, independent copy/save/share context actions,
and generic image viewers used elsewhere remain.

## SpeedCubeDB Square-1 Renderer Research

Primary evidence:

- [Square-1 CS page](https://speedcubedb.com/a/SQ1/SQ1CS)
- [Page's custom ijsm.js](https://speedcubedb.com/includes/ijsm.js?d=2)
- [Separately loaded PuzzleGen project](https://github.com/tdecker91/puzzle-gen)
- [PuzzleGen LICENSE](https://raw.githubusercontent.com/tdecker91/puzzle-gen/master/LICENSE)
- [PuzzleGen package metadata](https://raw.githubusercontent.com/tdecker91/puzzle-gen/master/package.json)

The recognition path is runtime SVG, not a static PNG or the page's PuzzleGen
PNG path. `.sqcube` elements carry `data-t`, `data-b`, side-color data `data-tr`
and `data-br`, dimensions and `data-display`. Custom `sqcubehelper` in `ijsm.js`
builds polygons through SVG.js 3.1.2. Edge/corner widths correspond to 30/60
degree sectors; the boundary polygons expose deformation, sticker boundaries and
colored side rings. The live DOM contains black polygon strokes and separate
`#D00000` slice-reference lines. Options include line/straight/background display
choices. Color characters supply fills, including grey ignored regions.

No independently licensed project named jcube/jCube was identified for this path.
The remembered name may refer to ijsm/icube helpers, but that is only an inference.
The custom script is publicly hosted on SpeedCubeDB; no explicit reuse license
was located. Public readability is not permission to copy it. PuzzleGen is a
different loaded dependency: its repository LICENSE says Apache-2.0 while its
package metadata says ISC. Resolve that inconsistency for any future adoption;
neither establishes a license for SpeedCubeDB's custom helper.

Side-ring/layer views provide recognition cues, but this inspection did not
establish that the custom helper models CubeFlow's exact `middleFlipped` state or
a complete physical middle-layer solid. Do not claim that it does.

Future design: feed the existing canonical sector state into an independently
written Alg recognition renderer; retain explicit deformation, side rings,
ignored-region masks, fixed red slice overlay, and separately modeled middle
state cues. Supply palette through face/color mapping rather than changing
geometry. Reproduce mathematical/display semantics, not unlicensed script code.
No new Square-1 renderer ships in this pass.

## Probability

Case rows use secondary caption text immediately before the disclosure chevron,
after any learned marker. It wraps with Dynamic Type rather than forcing a scale
factor or adding another metadata row. Missing probabilities produce no label.

Exact numerator/denominator metadata comes from the existing generation model:

- PBL: product of enumerated layer multiplicities; conditional denominator
  `576 * 576 - 4 * 4 = 331760`, across 1,935 entries.
- OBL: multiplicity in 4,900 enumerated color states, across 186 entries.
- CSP: slice-aligned boundary-state orbit multiplicity split over both count
  parities; denominator 14,712, across 180 entries.

Exact ratios are checked against existing probabilities, not fitted to a rounded
decimal. UI reduces general a/b fractions and derives percent from the same
counts with three significant digits: `1/10,368 · 0.00965%`. Only floating-point
data gets an approximate percent without an invented fraction. Stable sorting
prefers the exact value, retaining the existing missing-value/tie semantics.
These are conditional mathematical distributions, not empirical solve frequency.

## CSP Normal/Inverted Coverage

Retained 90 canonical cubeshapes and 180 Odd/Even entries. Added execution groups
inside each entry rather than adding new user-facing cases. The normal group
retains its setup/reference. The inverted group explicitly starts after setup +
`x2`, with a separately displayed layer alignment where applicable.

In the existing 12-sector model, rigid inversion is
`X(T,B,m) = (reverse(B), reverse(T), m)`. Independent stepwise proof establishes
`X turn(a,b) = turn(-b,-a) X` and `X slice = slice X`, including legality and
middle state. Applying the conjugated normal solution to the inverted starting
state returns `X(solved)`, a cube-shape state with even piece-cycle parity. The
goal is parity-controlled cubeshape, not a claim of fixed-color full puzzle solve.
The inverted counting reference is transformed too, so Odd/Even is deterministic
under the declared counting convention, not a heuristic or guessed Cale label.

For equivalence, enumerate legal top/bottom alignments, require identical sector
boundary geometry, then execute the normal reference and require exact even
piece-cycle parity. No names/string-similarity rule and no guessed string inverse.

Results:

- 16 parity presentations (8 geometry families) reuse their normal formula IDs
  after a proved alignment; 164 require distinct inverted references.
- 344 execution reference contexts after these merges: 343 explicit formula IDs
  plus the existing solved/no-turn identity reference. Not a preselected target.
- 360 starting presentations validated; 1,885 stepwise conjugacy checks; 2,880
  type-preserving relabelled inverted-state checks; the existing independent
  2,700 arbitrary-state parity-control checks also pass.
- Original setup/state/case IDs and taxonomy are unchanged. Existing canonical
  merging preserves distinct setup contexts; focused compatibility tests cover it.

The eight merged geometry families, each for both parities, have canonical
boundary keys:
