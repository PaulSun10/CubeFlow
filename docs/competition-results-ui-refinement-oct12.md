# Competition Results UI Refinement

October 12, 2026. Presentation-only continuation of the existing dirty worktree. No commit or push. This report supersedes the presentation portions of the earlier unified-results report, not its transport contracts.

## Implemented

- Official Results, native CubingChina Live and Scrambles share the selector surface: system background, continuous 4-point corners, existing border-free treatment, subtle internal divider, horizontal padding 10 and vertical padding 2. Event glyphs are 20 points in 30-point visual cells with zero inter-cell spacing; practical 44-point hit targets remain. Round and group label padding is 3 points vertically. Existing glyph ink-centering and record badge protections remain.
- The dark ambient lift is white at 0.065 opacity, radius 4, vertical offset 2. Light-mode ambient shadow remains clear; the Results list's pre-existing black shadow is unchanged. No new light shadow or conspicuous outline.
- Live now uses the same horizontal destination navigation as Official Results. Results remains the default; available Podiums, Records and Sum of Ranks retain verified data. Event/round state and Sum of Ranks gender selection survive destination changes.
- Persistent separate Official Results, Live and My Results capsules sit in normal flow immediately below navigation, horizontally scrollable when necessary. iOS 26+ uses native tinted interactive Liquid Glass; iOS 15-25 uses regular material. Official uses the existing Results purple (#8200DB light / #C27AFF dark), Live uses system orange, and My Results uses system blue. These are existing app/system colors, not newly inferred provider tokens. The existing Scrambles sky accent (#0069A8 light / #00BCFF dark) is unchanged.
- Official opens the existing Results destination. The camera Live action uses only verified photo-stream metadata: one stream opens directly, multiple streams use a native menu, no stream means no action. Trusted-link validation is unchanged. Normal Open Live Website is removed; genuine native-data errors retain the website recovery link.
- My Results uses an exact valid signed-in WCA ID among already available snapshot/record/podium/Sum of Ranks competitors, not just the selected round. A tap makes one on-demand competitor-results request and opens the existing native sheet. No global scanning, name matching or bulk round loading. Owned loading/retry work cancels on dismissal, leaving or backgrounding.
- Live headings share compact event icons, normalized titles and an ASCII hyphen. Verified status and unique recorded/expected count have separate soft semantic capsules; fresh viewers use person.2 without a badge, and Last updated is plain localized operator timestamp text. Existing 45-second freshness and omission rules remain unchanged.
- Only CubingChina's exact raw `smart` event displays localized Smart Cube with a lightweight Bluetooth vector. Selectors, Results, Podiums, Records, Sum of Ranks and native personal results use it. Transport keys/IDs are unchanged; international WCA styling is not renamed.
- Personal result rows retain 34-point height, ordinary fonts, rank/score widths and blue fill (0.035 light / 0.065 dark). The existing 1.5-point blue leading line now uses 0.34 / 0.42 opacity. A fixed localized Me / \u6211 badge follows the flexible truncated name, without moving score columns or changing WR/CR/NR badges.
- Chat is the sole bottom-right action. Essential message/result preferences are in the read-only Chat sheet menu, not lost with the removed bottom Settings action. The actual competition detail root uses a native bottom safe-area inset above the existing native TabView. No device-specific offset, global tab-bar replacement or hiding. An unavailable initial Live deep link does not show a dead Chat button.
- The existing Top Cubers section keeps its section container, ranking order, record provenance, badges, padding and adaptive wrapping, but removes each entry's capsule background. A hidden noninteractive/accessibility-hidden measurement of the same full layout determines the first three actual rows. Show N More counts the remaining complete cubers; no action appears when everyone fits. Stable entry IDs, 0.32-second ease-in-out fade/subtle movement and bounded native scroll-anchor compensation coordinate disclosure. Reduce Motion disables motion. Dynamic Type uses the same scaled font for drawing and wrapping measurement. No fixed-height clipping or fixed cuber count.
- Scrambles preserves the Event/Round/Group controls in their original arrangement and all scramble numbers, extra scrambles, diagrams and data behavior. Below the selector a secondary, left-aligned caption shows only the selected Group A/B/C and follows the existing selection immediately.

## Verified Website Contract

The hydrated [Beijing Sum of Ranks page](https://cubing.com/competition/Beijing-Autumn-Rivalry-2026/live/statistics/sum-of-ranks) and its [production route client](https://cubing.com/_nuxt/uhQEziaZ.js) were inspected for presentation semantics, not copied implementation code. Runtime native data still comes from the existing [public typed API](https://api.cubing.com/competitions/Beijing-Autumn-Rivalry-2026/live/statistics/sum-of-ranks).

The table shows position, competitor, region, sum and every per-event rank, with horizontal scrolling. Native additionally exposes the verified entered-count field; the website uses that field in ties but does not display a separate count column. All/Male/Female filtering uses exact returned genders; unknown/absent values remain only in All. Server ordering, sums, per-event ranks and entered-event membership are preserved. Display position is derived after filtering: adjacent rows tie only when both sum and count match. This is explicitly website-equivalent display numbering, not an API-authored overall rank. Unentered rank values remain visible but secondary.

The complete captured fixture has 362 unique competitors, 309 male / 53 female, and 18 event columns. The first female row is Xintong Wang. Native uses stable typed competitor IDs and a lazy row stack, not a reduced card list, WKWebView or runtime HTML scraping.
