# CubeFlow 1.0 Focused Depth Correction

Current dirty-worktree correction, 2026-10-05. This supplements, not replaces, the earlier depth-pass evidence. No commit, push, deployment, or staging. Physical acceptance is not inferred from automated verification.

## Product And UI Changes

- Data keeps the independent solve-number column, prominent time, input provenance and selection semantics. Row vertical padding is 10 points instead of 6; date and scramble use Dynamic Type `subheadline` instead of `caption`.
- The blue/orange PB banner is unchanged. Confetti now uses the actual UIKit/CAEmitterLayer implementation of [SwiftConfettiView](https://github.com/ugurethemaydin/SwiftConfettiView), commit `7b0d18301b9135ea62274d470e050fe032dace91`. Default Rain uses intensity 0.75, density 1.5, the original five-color palette, original particle asset/size/spin/velocity variation, gravity ramp and rain settling. No sound, haptics, style selector or alternative preset. Default Rain does not enable the library's optional extra background-depth layer; that behavior is preserved rather than arbitrarily substituting Perfect.
- The MIT source and original four particle assets are vendored, with the license and source/adaptation notice in `Resources/ThirdPartyNotices`. CubeFlow adds synchronous emitter cancellation and namespaced asset lookup. The existing 3.2-second celebration limit remains; leaving Timer/backgrounding/replacing the celebration cancels it. Reduce Motion creates no emitter. Repeated start/cancel is tested for zero remaining layers. [ConfettiSwiftUI](https://github.com/simibac/ConfettiSwiftUI) was also inspected; it is MIT, but does not directly implement the specifically requested Default Rain target.
- Timer diagrams have a native Thin/Thick setting. Thin remains the default. Thick uses a 1.6 nominal multiplier. NxN/FTO derive pixel stroke and padding together without changing grid geometry. Other puzzle paths retain Thin geometry; Thick reserves worst-case miter reach and a transparent backing pixel before fitting.
- Long Scroll now derives its available space from the rendered ordinary Timer/manual-entry frame and the scramble origin in the same named coordinate space, leaving 12 points. A bounded font/layout estimate is only the initial/preview fallback. Scroll height subtracts the user's top-placement offset, so that offset cannot push the viewport into Timer. No event-specific height or large safe-area reservation. Smart Cube composition is not reworked.

## Canonical Cases And Persistence

The audit covers **49 bundled sets / 8,970 appearances**, not 8,970 distinct mathematical cases. The generated relationship manifest has **622 shared groups / 1,303 appearances**; every membership resolves to a bundled case.

Proven overlap families:

- All 21 PLL cases and 472 ZBLL cases have corresponding 1LLL entries, using identical setup within the same full-last-layer solving goal.
- Square-1 EP, PBL, Lin aggregate, Lin PLL/parity PLL and existing parity entries overlap using independently evaluated sector states, modulo stated layer AUF/cyclic layer-label equivalence. Setup context remains attached to the algorithms. The manifest includes 97 EP appearances and 129 PBL appearances in shared groups.
- F2L/advanced F2L and 2x2 full-solving families were audited too, but no overlap passed the current strongest exact partial-sticker/setup criteria. COLL/CMLL and similarly named cases from other puzzles/goals are deliberately not merged on their names or similar pictures alone.

Learned state reads both canonical IDs and legacy per-set keys. A write updates canonical plus legacy aliases for downgrade compatibility; unlearning clears aliases, and unknown/future JSON data is preserved. No destructive eager migration. Weak-review aggregation uses canonical identities without rewriting historical records or their provenance. Existing favorites are set-level; there is no case-level favorites store to migrate.

Pools deduplicate only whitespace-identical notation with a compatible setup context. Sources/tags are retained. AUF-equivalent cases with different setups remain explicit algorithm groups, not a detached interchangeable move list. PLL's single empty-setup Orientation 0 wrapper is a base pool and now participates in merging; genuine directional groups are left intact. Raw-case indexing avoids repeated full-set scans. Two legacy EP names have setup-state aliases (`o_w`/`o_w_2` to `oa_w`, and `ua_ub` to `ub_ua`); this is state evidence, not a claim that those names are interchangeable under every teaching convention.

### PBL And EP

The permitted [PBL-Manager](https://github.com/charlieharris0n/PBL-Manager) data, commit `18cf975e5e22c474be8788eab4e4cb469cf90c1b`, describes 44 one-layer recognition families: 22 even and 22 odd. The old 967 references are `22^2 + 22^2 - 1`: matching-parity layer pairs, excluding solved/solved. They are recognition families, not 967 independently chosen AUFs or 967 curated speed algorithms. The missing cross-parity complement is `2 * 22 * 22 = 968`.

The source algorithm arrays are empty. New parity references compose its MIT setups with the **already present** `adj_parity` seed and independently match the requested native state. The seed's legacy SpeedCubeDB attribution is not proof of redistribution permission. Release rights review remains required; no blanket MIT claim is made for inherited algorithm content.

EP genuinely includes parity: [Sarah Strong's EP reference](https://sarah.cubing.net/square-1/ep) explicitly distinguishes parity entries and lists 99 cases. The added 50 references keep corners solved and cover the complementary edge-parity family. No separate top-level Parity EP/PBL set is introduced. Existing signed setup geometry and complete upper/lower EP images are preserved.

### OBL

Independent enumeration gives `choose(8,4)^2 = 4900` upper-color corner/edge assignments. Quotienting independent U/D quarter alignment and global upper/lower color inversion gives 186 orbits. All 4900 color assignments were reached by CubeFlow's own cube-shape-preserving search, and each bundled setup/inverse returns exactly to its native starting state. The [OBL guide](https://sq1obl.com/learn/) uses its own reduced learning tree; that reduced-tree count is not mixed with the 186-orbit convention. No website algorithms, artwork, case names or GPL implementation were imported. Curated ergonomic algorithms remain permission-gated.

### CSP: Deterministic, Convention-Aware

Primary behavioral references: [SpeedCubeDB CSP Tracing Tool](https://speedcubedb.com/SQ1/Trace), [Brandon Lin's CSP tutorial](https://brandonlin.com/cubing/csp.html), and the [Squanmate author's tool](https://github.com/mikavilpas/squanmate). The tracing tool has explicit top/bottom counting positions and color subcounts; shifting counting position can change its odd/even label. It is not a heuristic confidence signal. Lin's reference-scheme description likewise counts permutation swaps, and explicitly warns that reference alignment can reverse which solution is appropriate. Public availability alone is not algorithm redistribution permission.

CubeFlow independently reaches 7,356 slice-aligned shape/parity states: 3,678 anchored shapes with two permutation signs, grouped into 90 families under independent layer rotation and top/bottom exchange. Chirality is not collapsed by arbitrary reflection. Each family stores one explicit oriented counting reference, sector positions, convention ID `cubeflow-piece-cycles-v1`, swap count and parity. Counting extracts the 16 actual piece IDs, validates the same shape/type slots and counts `cycle length - 1`. Missing/invalid IDs or a mismatched counting frame return no result rather than inferred parity.

This is the mathematically exact full-piece cycle convention, **not an unvalidated conversion of Cale color counting or the tracing tool's labels**. Its even/odd solutions are matched to that reference. Different top/bottom placements must be brought to the stored reference orientation before using it. Both variants retain separate canonical identities; shape-only CS and parity-controlled CSP have different solving goals and do not share learned state by accident.

All 180 selected setup/reference solutions return exactly to solved. All 180 paired opposite solutions return to cube shape with odd permutation parity. A separate deterministic validator also checks **2,700 arbitrarily relabelled corner/edge states**: selecting by computed trace yields even cubeshape in all 2,700; selecting the opposite yields odd cubeshape in all 2,700. This demonstrates parity control beyond tautological setup/inverse checks. Middle-layer flip is separate from this piece-parity count.

The bounded UI addition is CSP -> cubeshape child row -> odd/even reference cases, using the existing diagram/provider/training infrastructure. C/E width patterns identify the exact independently generated geometry; legacy CS has inconsistent setup/name relationships and is not used to assign guessed CSP names. There is no new tracing-tool UI or trainer redesign. Familiar ergonomic case names, Cale convention conversion and curated CSP algorithms remain source/validation-gated.

### Probability And Slice Organization

- PBL weights use actual symmetry multiplicity over `576^2 - 16 = 331760` nontrivial oriented cube-shape layer-permutation states. They sum to one over both parity subsets; listed cases are not assumed equiprobable.
- OBL weights are each orbit's multiplicity divided by 4900.
- CSP weights use multiplicity over the independently enumerated 7356 **slice-aligned shape/parity states**, then split each family equally across its two count parities. This is a specified conditional mathematical model, not measured WCA scramble frequency.
- Most/least-likely sorting appears only when the cases have known probabilities. No guessed EP/3x3 probabilities. Square-1-only slice sorting counts the minimum listed reference formula's slashes; it is not a proof of globally optimal slice count. Existing default grouping/order remains available.

## Images And Palette Research

PNG is cheap to display but cannot fundamentally own canonical palette/orientation. SVG/vector can own geometry, but per-cell parsing or a WebView per list row is unnecessary overhead. UIKit state-to-raster rendering fits the existing iOS list/cache architecture and avoids a new SVG dependency.

3x3 last-layer cases with usable canonical sticker metadata now render from color identities using CubeFlow's existing custom cube palette. Square-1 cases render from native setup state using its custom palette and unchanged accepted padded canvas. Palette and quarter-turn orientation are explicit renderer/cache inputs; palette storage invalidates the relevant SwiftUI surfaces. The NSCache remains bounded at 128 images / 32 MiB, with per-set lazy source indexes. Transparent canvases preserve light/dark compositing. Legacy partial-state/unsupported-puzzle PNGs remain honest fallbacks, not falsely recolored by pixel substitution. This is not a claim of complete palette/orientation conversion for every legacy asset, nor a new orientation customization UI.

Behavioral research used official [csTimer image source](https://github.com/cs0x7f/cstimer/blob/master/src/js/tools/image.js) and [palette settings](https://github.com/cs0x7f/cstimer/blob/master/src/js/kernel.js), not GPL code incorporation. They define puzzle-specific custom color arrays, including the 12-color Megaminx arrangement already reflected in CubeFlow's custom palette. No current `mf8`-labelled preset was verified in the inspected csTimer settings/renderer sources. The label is therefore not invented as a new preset. Preserve per-puzzle custom schemes; an MF8 preset needs an exact face-order/source record, not merely a brand name or color list.

## FTO Performance

The existing UI prefetch is a single slot; after it is consumed, an FTO miss must wait for the serialized JS solver. Prewarming the general TNoodle bridge did not populate the FTO solver. JSContext confinement itself is legitimate and is retained.

FTO now independently prewarms a bounded four-entry FIFO and refills immediately on consumption, one solver job at a time. Cached delivery uses a short lock, not `queue.sync` behind solver work. It has its own delivery queue so a cold FTO miss cannot hold up NxN. Each entry is generated fresh with the unchanged random-state solver and consumed once. There is no result reuse, fixed-scramble trick or weakened randomness.

Focused simulator evidence: four warmed deliveries took **0.028 ms total** in the final run; generation/refill samples ranged roughly 21-524 ms. The uncached path still has genuine solver cost and a sustained burst can exhaust the reserve. The prior approximately two-second hardware delay is user evidence, not a before/after measurement on this simulator. Physical sustained-refresh/cold-start acceptance remains necessary. Independent `cubing@0.63.8` puzzle-geometry comparison still passes all 98 full 72-sticker states.

## Concurrency, Xcode And iOS 13

`SWIFT_DEFAULT_ACTOR_ISOLATION=MainActor` was implicitly actor-isolating StoredColorData's pure value conformance. The root fix is a nonisolated Codable/Equatable/Sendable RGBA value; Color-to-UIKit extraction remains MainActor. No scattered BLE annotations or warning suppression. Detached equality and Codable round-trip pass; no StoredColorData isolation warning appears in the final focused build log.

Recommended settings audit:

- Accept explicit `DEAD_CODE_STRIPPING=YES` in the two project configurations.
- String Catalog symbol generation was already enabled for the app: retain it, no catalog conversion/churn.
- Add/validate requested strings in all 19 existing `.strings` catalogs. Defer broad missing-localizability warning enforcement until legacy English/content/source strings have a deliberate audit; do not suppress new errors.
- Reject moving deployment-target macros or an automatic raise to the SDK's recommended 17.0. App deployment remains explicitly 15.0; unrelated platform targets remain unchanged.

Concrete compatibility probes with installed Xcode 27.2 / SDK 27.2:

- `-showBuildSettings IPHONEOS_DEPLOYMENT_TARGET=13.0` can represent 13.0.
- A standalone arm64 C dylib links with `LC_BUILD_VERSION minos 13.0`; therefore the linker does not categorically forbid representing iOS 13 binaries.
- The installed SDK's supported deployment list/minimum is 15.0; its Swift concurrency minimum is 15.0. [Apple's Xcode requirements](https://developer.apple.com/xcode/system-requirements) likewise list supported deployment targets separately from SDK/runtime availability.
- A real SwiftUI availability probe at target 13.0 fails on APIs used by CubeFlow: AppStorage (14), `.task` and `foregroundStyle` (15). AppStorage/modern asynchronous view lifecycles occur broadly across the project, not in one confetti view.
- Bundled arm64 TNoodle dylib reports minimum iOS 11.0, so it is not itself the current 13 blocker. Vendored SwiftConfettiView declares iOS 13 and has no new package minimum blocking it.
- [Apple submission SDK requirements](https://developer.apple.com/news/?id=ueeok6yw) concern the SDK used to build, not an instruction to set deployment target to that SDK version. They do not demonstrate that this app currently supports iOS 13.

Conclusion: actual CubeFlow iOS 13 build/runtime/distribution feasibility is **not established**. Keeping 15.0 is supported and avoids a speculative broad port. A future 13 feasibility project needs compatible toolchain support, availability/property-storage/task/navigation/material fallbacks, minimum-OS device testing, and a signed Release archive/export with distribution validation. An unsigned Debug build cannot establish App Store acceptance; no upload, signed archive or release is performed here. Retain modern behavior on new systems and do not create a separate Legacy app.
